## 1. F10 채택 대시보드 디자인

### 선택과 근거

**베이스 = "조용한 매트(Calm Mat)"의 IA 골격**(PRD §F10 5개 지표를 정확히 1:1 매핑, 최소·정돈, `mx-auto max-w-screen-md` 단일 컬럼) **+ "습관 우선"의 스트릭 히어로 승격**(PRD §10 "주 3회 = 습관") **+ "매트 리포트"의 streak-dots 디테일·12버킷 상한·캡션 규율**을 그래프트.

- **Calm Mat 골격인 이유**: PRD §F10 verbatim 지표는 5개("매트 타임 / 종목별 세션 분포 / 주·월 빈도 / 스트릭 / 최다 복습 기술"). 군더더기 KPI 타일 없이 1:1 매핑. 스트릭을 두 번 그리는 중복 위젯 제거.
- **스트릭 히어로 승격 이유**: PRD §10 성공 신호(주 3회 = 습관 형성)가 동기 핵심. 상단 한 행 = **[총 매트 타임 | 연속 기록]** 2-up. 연속 기록 카드에 **streak-dots**(IntensityDots 관용구) 내장해 today-grace를 시각적으로 납득. "주 3회 목표선"은 별도 섹션 신설 없이 **빈도 차트(주간 모드) 위 점선 기준선 + 달성 막대 빨강 신호**로 흡수 → 섹션 5개 유지.
- **빨강 절제 이유**: `--primary`(빨강)는 (a) 스트릭 현재 수치, (b) streak-dots 훈련일/오늘, (c) 빈도 주간 "주3회 달성 막대", (d) 빈도 토글 활성 인디케이터, (e) 액션(더보기/EmptyState CTA)에만. 차트 시리즈 기본 막대는 중립(`--text-default`), 종목은 DISCIPLINE_META 틴트. "빨강 = 신호" 단일 의미 보존.

## 2. F10 파일 계획

### 슬라이스 결정: **`widgets/stats`** (features 아님)
근거: stat 컴포넌트는 `entities/discipline`의 DISCIPLINE_META + `entities/session`의 집계 헬퍼를 import. FSD 방향(widgets → features → entities → shared)에서 widgets가 entities를 import하는 것은 합법. F2에서 확립한 "SessionCard 재사용 컴포넌트는 widgets" 원칙과 일관. stats-screen은 app 레이어가 widgets를 조합.

### 집계 lib 위치 / fetcher / dayjs init (스펙 충돌 해소)

**충돌 1 — dayjs 플러그인 wiring**: F10 data spec은 `isoWeek + weekday + customParseFormat`을 `shared/lib/dayjs.ts` 측효과 모듈로 wire. F2 spec은 "wire하지 마라". **해소: 둘 다 옳다 — 다른 계산이다.** F2(주/아젠다)는 Sun-start를 `d.subtract(d.day(),'day')`로 계산 → 플러그인 불요. F10 빈도 차트는 **ISO 주 키의 연말 경계 안정성**을 위해 isoWeek 필요. **결정: `shared/lib/dayjs.ts` 생성, F10 코드만 거기서 import. F2는 bare dayjs 유지(현 6개 파일 패턴 그대로).** dayjs init 측효과 import는 **`src/app/providers.tsx` 최상단**에 `import '@/shared/lib/dayjs';`(검증 완료: providers.tsx가 `'use client'` 전역 클라이언트 진입점/QueryClientProvider 래퍼). + stats.ts도 configured dayjs를 직접 import(유닛 테스트가 app bootstrap 없이 플러그인 확보 — belt-and-suspenders).

**충돌 2 — 집계 lib 위치**: `entities/session/lib/stats.ts` 유지(옳음). 순수 집계는 I/O·React·DISCIPLINE_META 의존 없음(Discipline enum만 `shared/model/enums`). entities 레이어 적합. UI 차트만 widgets/stats.

- **ISO주 vs Sun-start 라벨 불일치**: F10 빈도는 ISO주(월요일 시작) 키로 안정성 확보, **사람용 라벨은 별도 파생**. F2 캘린더는 Sun-start. 두 기능이 같은 "주"를 나란히 보이지 않으므로 혼동 없음. 빈도 라벨이 Sun-start여야 한다는 요구 확인되면 weekday 플러그인으로 전환.
- **FSD 위반 (최상위 위험)**: Week/Agenda를 features/calendar-view에 두고 SessionCard import하면 상향 위반. **반드시 widgets/day-detail.** lsp_diagnostics + import 경계 확인 필수.
